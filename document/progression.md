# レベル・経験値・技能成長

`data/progression.lua` が成長ルールの正本。敵の報酬は各Lua定義の `movable.experience_reward`、武器が使う技能は `item.weapon.skill` で設定する。Rustは経験値付与、消費、乱数、成長値の反映を共通処理として扱う。

## レベル

- 初期レベル1、次レベルに必要な経験値は `100 × 現在レベル`。余剰分は次へ繰り越し、一度に複数レベル上がる。仮上限は100。
- プレイヤーの攻撃・射撃・投擲で敵を倒すと、その敵の報酬を一度だけ獲得する。プレイヤーが最後に傷つけた敵が出血で死亡した場合も対象。固定物の破壊、自傷、プレイヤーが関与しない敵の死亡からは獲得しない。
- レベルアップごとに筋力・敏捷・器用さ・精神力を独立に25%で選び、選ばれた能力を各1上げる。全て外れた場合は4能力から均等に一つを選ぶため、毎回1つ以上が上がる。
- 最大HP・最大正気度は各1〜10、最大スタミナは1〜5の独立な一様乱数で毎回上昇する。生存中の現在HP、現在スタミナ・正気度も対応する上昇量だけ増え、減っていた分は維持する。技能はレベルアップでは上げない。
- 成長用乱数は戦闘・病気用と別に保持する。死亡・リスポーン後もレベル、経験値、能力値、最大HP・最大スタミナ・最大正気度、技能と練習進捗を保持する。
- 通常画面上部と `@` のプロパティでレベル、経験値、次レベルまでの残りを確認できる。

敵の報酬はHP・装備・行動を踏まえた仮設定。実プレイでのバランスは未確認。

## 能力・スタミナ・正気度

能力は筋力・敏捷・器用さ・精神力の4つ。体力 `tairyoku`、知力 `tiryoku` と社交技能 `syakou` は読込対象から削除した。
能力補正は `floor((値 - 8) / 2)`。8で0、10で+1、6で-1となる。

- 器用さ：近接・素手・射撃の命中へ能力補正を加える。既存の敏捷・武器・技能の命中補正と合算する。制作成功率には能力補正×5ポイントを加算し、従来の最小/最大成功率の範囲に収める。出来の抽選への補正は加えない。制作係数は `data/production/recipes.lua` の `dexterity_step`。
- スタミナ：体力の代わりに独立した現在値/最大値を持つ。初期上限100。走行の消費・回復は維持し、成長後の上限まで回復する。HP死亡の復帰時は成長後の最大値へ戻す。
- 精神力：サイキック威力は `max(0, 基礎威力 + 能力補正×psychic_power_step)`。正気度の被害は `max(0, 威力 - 防御側の能力補正×sanity_resistance_step)`。0威力は補正にかかわらず0。負の精神力補正は被害を増やす。係数は `data/mental.lua`、現在はいずれも1。乱数による抵抗判定は追加していない。
- 正気度：Luaの初期 `sanity` を初期上限として、現在値/最大値を保持する。プレイヤーが0になるとグールへ変化してゲームオーバー。HP死亡と同時でもゲームオーバーを優先し、リスポーン・成長・世界の更新を停止する。Enter/Esc/Ctrl+Qで終了する。

`sanity_damage` と `psychic_attack` の共通Lua effectを接続済み。標準データには具体的なサイキック能力・発動キー・正気度攻撃をする敵はまだない。したがって通常プレイで正気度が減る機会は現時点ではない。正気度を回復する専用操作も未実装。

## 技能

次の1上昇に必要な使用回数は `10 + 現在技能値 × 2`。上昇時に使用回数を0へ戻し、仮上限100とする。初期技能値は既存Lua定義を引き継ぐ。

| 技能 | 練習する操作 | 現在の効果 |
| --- | --- | --- |
| 近接武器 | 生存中の生物に対する有効な近接攻撃・素手攻撃。外れも1回 | 5ごとに命中+1 |
| ライフル | 銃で生存中の生物へ発射。外れも1回 | 5ごとに命中+1。現行では拳銃も含む |
| 弓 | クロスボウで生存中の生物へ発射。外れも1回 | 5ごとに命中+1 |
| 盾 | 使用できる手に盾を持って生物の攻撃を受ける。回避しても1回 | 使用可能な盾の装備中、5ごとにDV+1 |
| 投擲 | 有効な投擲1回 | 練習値の保持・表示。投擲威力などへの補正は未実装 |
| 木工・金属加工・裁縫・料理 | レシピが指定した技能を作業1ターンごとに各1回。完成時の失敗も対象 | 既存の制作成功率と出来の計算へ反映 |
| 電子工作 | 共通制作APIは対応するが、現行12レシピに指定なし | 保持・表示。電子工作レシピを追加すれば制作判定に使える |
| 解錠・ハッキング | 現在の定義には専用操作なし。Lua共通APIから追加可能 | 練習値の保持・表示。専用操作と効果は未実装 |

弾切れ・射程外・制作条件不足・無効な投擲では練習しない。操作案内やプロパティの閲覧・スクロール、待機、レシピ開始だけでも増えない。制作を中止しても実施済みの作業の練習は残る。`@` の【技能】に現在値、使用回数、次までの残り回数を表示する。

## Luaの拡張

`item.weapon.skill` は既存技能名を指定する。未指定の旧定義は `melee_weapon` として扱うため、新しい射撃武器には明示する。

```lua
weapon = {
    skill = "bow", -- melee_weapon / rifle / bow 等の既存技能名
    -- 既存の武器パラメータも必要
}
```

実際に操作が成立したときに、hookのeffectsから一回分の練習を付与できる。閲覧や失敗時には返さない。effectsの途中でエラーがあれば練習も含めて取り消す。

```lua
{ type = "practice_skill", target = event.user, skill = "picking" }
```

技能名は `melee_weapon`, `shield`, `rifle`, `bow`, `touteki`, `picking`, `hacking`, `wood_craft`, `metal_craft`, `denshi_craft`, `saihou`, `cooking`。練習による成長対象はプレイヤーのみ。敵はLuaの初期能力・技能値を維持する。

Luaスナップショットには `level`, `experience`, `skills`, `skill_practice` と `stamina` / `sanity`（`{current,max}`）、`ghoul`、変化後の `faction` を公開する。設定変更は再起動時に反映される。

## 画面配置・配色

80×50セルのうち上部4行、マップ38行、操作案内2行、ログ4行、余白1行、数字登録1行を使う。通常・試験マップは60×38へ拡張し、既存配置の座標を維持する。ズームでも操作案内の位置は固定し、マップだけを拡大する。

UIの配色は `src/ui/theme.rs` に集約。[gruvboxの定義](https://github.com/morhetz/gruvbox/blob/master/colors/gruvbox.vim)を参考に、背景#282828、通常文字#d5c4a1、選択・見出し#d79921、青緑の枠#83a598、補助文字#7c6f64、制作不可#504945を使う。EntityのPNGはAsh & Rust 32を維持する。
